# Добавление главы

Глава — один файл `chapter.json`. Темы живут внутри него массивом `topics`;
отдельных `.md`-файлов у тем больше нет.

У самой главы только `order`, `title` и темы: описания и `learning_outcome`
у главы нет (убраны в июле 2026) — в miniapp у главы нет своей страницы,
она показывается заголовком над списком тем. Не возвращать.

## Что спросить (если не указано)

- Книга (slug или название)
- Порядковый номер и название главы
- Названия тем главы (по порядку) — можно списком сразу

## Шаги

1. Определи книгу: `books/<slug>/`.
2. Создай папку `books/<slug>/chapters/<NN-slug-главы>/`, где `NN` — двузначный
   порядковый номер (`01`, `02`…), slug главы — kebab-case (транслит рус. названия).
3. Создай `chapter.json` — глава целиком, вместе с темами:
   ```json
   {
     "order": 1,
     "title": "…",
     "topics": [
       {
         "id": "<book-id>-<номер главы>-<номер темы>",
         "title": "…",
         "speakers": ["Имя"],
         "video_youtube": "",
         "video_vk": "",
         "presentation": "",
         "resources": []
       }
     ]
   }
   ```
   Тема несёт только название, спикеров и ссылки — описаний, инсайтов и мнений
   спикеров у тем нет. Пустые поля оставляй как `""` / `[]`: ссылки и спикеры
   дозаполняются после встречи.
4. При необходимости обнови `total_chapters` в `books/<slug>/meta.json`.
5. Проверь `JSON.parse` и `npx prettier --check` по новым файлам.
6. Коммит: `feat(books): добавить главу <NN> "<Название>"`. Не пушить.

## Соглашения

- `id` темы уникален в рамках книги, формат `<book-id>-<глава>-<тема>`
  (напр. `docker-intro-1-2`) — на него ссылаются встречи (`topic_id`,
  `topic_ids`, `recordings`) и брони докладов в боте. Менять id нельзя.
- Порядок тем задаётся порядком в массиве `topics`.
- Спикеров для аватарок заводи скиллом `add-speaker`.

## Связанные скиллы

Карточки к главе: `add-flashcards`. Встреча по главе: `add-event`.
